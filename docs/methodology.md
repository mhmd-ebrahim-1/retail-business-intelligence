## 2. Data Cleaning & Transformation Log

| # | Issue Identified | Detection Method | Decision Taken | Rationale & Business Impact |
| :--- | :--- | :--- | :--- | :--- |
| 1 | Inconsistent Column Naming (Spaces & Mixed Case) | Schema Audit | Renamed to standardized `snake_case` | Ensures universal compatibility across SQL engines, Pandas, and Python scripts. |
| 2 | String Dates (`MM/DD/YYYY` & `DD/MM/YYYY`) | Type Inspection | Parsed using mixed format detection to ISO `YYYY-MM-DD` | Eliminates parsing errors and allows accurate day-level date differences. |
| 3 | Postal Code Truncation & Type Inconsistency | Column Profiling | Converted to integer, zero-padded to 5 digits (`05401`) | Preserves leading zeros in North-Eastern US zip codes for accurate geospatial joins. |
| 4 | Whitespace in Text Attributes | String Value Inspection | Applied `.str.strip()` across all categorical string fields | Prevents duplicate categories caused by accidental trailing spaces (e.g. `'Consumer '` vs `'Consumer'`). |
| 5 | Extreme Discount Values Impacting Profit | Distribution Analysis | Maintained raw transaction values; created categorical `discount_band` features | Preserves transactional authenticity while providing analytical slicing. |

## 3. Customer RFM Segmentation Framework

### A. Core Metrics Calculation
- **Recency ($R$):** Days elapsed between the customer's last purchase date and the reference analysis date (`2017-12-31`).
  $$R_i = \text{Reference Date} - \max(\text{Order Date}_i)$$
- **Frequency ($F$):** Total number of distinct orders placed by the customer.
  $$F_i = \text{Count Distinct}(\text{Order ID}_i)$$
- **Monetary ($M$):** Cumulative revenue generated by the customer.
  $$M_i = \sum \text{Sales}_i$$

### B. Quantile Scoring (1 to 5)
Customers are ranked into 5 equal quintiles (20% bins) for each metric:
- $R\_Score$: 5 (Top 20% most recent) to 1 (Bottom 20% least recent).
- $F\_Score$: 1 (Lowest frequency) to 5 (Highest frequency).
- $M\_Score$: 1 (Lowest lifetime spend) to 5 (Highest lifetime spend).

### C. Segment Assignment Rules
```python
def assign_segment(r, f, m):
    if r >= 4 and f >= 4 and m >= 4:
        return "Champions"
    elif r <= 2 and (f >= 4 or m >= 4):
        return "Cannot Lose Them"
    elif r >= 3 and f >= 3:
        return "Loyal Customers"
    elif r <= 2 and f >= 2:
        return "At Risk"
    elif r >= 4 and f >= 2:
        return "Potential Loyalists"
    elif r >= 4 and f == 1:
        return "New Customers"
    elif r >= 3 and f <= 2:
        return "Promising"
    elif r <= 2 and f <= 2 and (r > 1 or f > 1 or m > 1):
        return "Hibernating"
    else:
        return "Lost"
```

## 4. Statistical & KPI Calculation Standards
- **Profit Margin (%):** Calculated as $\frac{\sum \text{Profit}}{\sum \text{Sales}} \times 100$, NOT the average of line-item margins (which would mathematically bias towards small low-dollar items).
- **Average Order Value (AOV):** Calculated as $\frac{\sum \text{Sales}}{\text{Distinct Orders}}$.
- **Year-over-Year (YoY) Growth:**
  $$\text{YoY Growth } \% = \frac{\text{Metric}_{t} - \text{Metric}_{t-1}}{\text{Metric}_{t-1}} \times 100$$
